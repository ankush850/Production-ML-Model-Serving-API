# Reference Repo Notes

Learnings from the seven cloned reference repos (in `reference/`, untracked) and which
of our files they influenced. No code was copied verbatim — all our code is original;
ideas only where the reference license is missing or restrictive.

| Repo | License | What we learned | Influenced |
|---|---|---|---|
| [ml-pipeline-engineering](https://github.com/bodywork-ml/ml-pipeline-engineering) | MIT | Timestamped `.pkl` artifacts in S3 "models" folder; serving entrypoint downloads the latest model into memory at startup, then starts uvicorn; Pydantic payload models with constrained fields (`ge=0.0`, enum categories). | `src/storage/s3_store.py`, `src/api/model_loader.py`, `src/api/schemas.py` |
| [bodywork-pipeline-utils](https://github.com/bodywork-ml/bodywork-pipeline-utils) | Proprietary (ideas only) | `S3TimestampedArtefact` class: timestamp parsed from the object key, sorted to find the latest; model metadata (git commit hash, creation time, hash) stored alongside the pickle; helpers `put_file_to_s3` / `find_latest_artefact_on_s3`. | Version naming `<YYYYMMDDTHHMMSSZ>` + `metrics.json` metadata fields (`git_commit`, `created_at`), `get_latest()` design |
| [networksecurity](https://github.com/akkiyolo/networksecurity) | Apache-2.0 (ideas only) | `S3Sync` folder-sync helper (wraps `aws s3 sync`); pipeline layout `cloud/ components/ entity/ logging/`; CI → ECR build/push → self-hosted EC2 runner pulls image, stops old container, runs new one with env vars from secrets. | `src/storage/s3_store.py` download-to-local-dir semantics; `.github/workflows/ci.yml` deploy job (ECR + EC2 pull/restart, secret names) |
| [intent-classifier](https://github.com/princ0301/intent-classifier) | none (ideas only) | Clean `src/storage/s3.py` (boto3 client factory, upload/download/exists/list keyed by settings) and `src/monitoring/drift.py` (reference vs current window, drift-share summary, degraded confidence checks); CI job that downloads artifacts from S3 then runs serving tests. | `src/storage/s3_store.py` client factory, `src/training/drift.py` report structure, `tests/test_api.py` scenarios |
| [mlops-fastapi-microservice](https://github.com/ivesfurtado/mlops-fastapi-microservice) | MIT | Minimal layout: `src/core/server.py` app factory + `src/api/v1/routes.py` + `model_service.py`; slim `python:3.12-slim` Dockerfile, workdir `/app`, uvicorn CMD; one-shot EC2 deploy workflow (test → buildx → docker hub → ssh: pull, stop, run). | `Dockerfile`, `docker-compose.yml`, `src/api/main.py` layout |
| [TheSentryAI](https://github.com/DeepActionPotential/TheSentryAI) | none (ideas only) | Per-role Dockerfiles (`Dockerfile.api`, ...); deploy workflow: `appleboy/scp-action` syncs code to EC2, then `appleboy/ssh-action` installs Docker if missing, stops/removes old containers, rebuilds, runs with `--env-file` and volume-mounted model dir. | `.github/workflows/ci.yml` deploy job SSH steps (sync → rebuild → restart, `.env` on host) |
| [ml-deployment](https://github.com/SuperMBA/ml-deployment) | none (ideas only) | Blue/Green serving: two FastAPI versions behind Nginx, switch via `proxy_pass` + `nginx -s reload`; health endpoint exposes the active model version so you can verify the switch; rollback = point traffic back to blue. | README "Rollback / Blue-Green bonus" section only |
